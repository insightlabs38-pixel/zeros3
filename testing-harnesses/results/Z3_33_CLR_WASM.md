# Z3-33 — CLR/.NET and WebAssembly indexed-reference frontier
Laboratory only; production files untouched (diff empty). Code: `z3/clrz3`, `z3/wasmz3`, `z3/econx` (cutters, piece packing, index-node wrapper extracted mechanically from `cmd/z3mb`), `z3/idxref` (+`AutoK0`, coder experiments), `z3/pdelta` (+`Attribute`), `z3/repz3/kinds/clr.go` (lab `KindCLR` = 12), drivers `cmd/z3clr|z3wasm|z3refc`, oracles `z3/oracle/clrwasm`. Sizes: packed M/K added to a store holding the earlier revisions (production pack rule, 96 B/ref, ~64-group index nodes). Every row carries an evidence class.
**Question → answer.** Does the DEX phenomenon generalize? **CLR: yes.** In real assemblies 58–69 % of the *changed* bytes are index/token/RVA renumbering and only 0.2–1.4 % (7.8 % across a major version) is true change; a masked payload plus semantic-identity references rebuilds every assembly exactly, cuts five real histories 14–34 % vs production CDC (2–15 % vs the best structure-only baseline) and patch steps 3.5–9×, at +10…+24 % first sight. **Wasm: no.** Real revisions change code, not indexes (index 0.3–9 % of changed bytes, code/data 55–96 %): normalization loses to CDC on real histories (+2…+14 %), although synthetic index shifts gain 2.5–9× vs CDC and 4–18× vs record groups. A **component-local dictionary never beats `AutoK0`** (+13…+15 % vs fixed prefixes on DEX/CLR; −7…−17 % on Wasm only); **candidate-table-sized prefixes (`AutoK0`) cut reference bytes 11–33 %** except where tables are huge (DEX).
**Decisions.** CLR representation `PROMOTE_TO_I2` · Wasm representation `KILL` · local reference dictionary `KILL` (AutoK0 kept) · `INDEX_SUBSTRATE_PARTIAL` · **CLR_WASM_WAVE_READY**

## 8. Coverage, shared substrate, portability, reuse
Exact coverage (all through `KindCLR`/`prove`: serialize, drop analysis, reload, rebuild; length, SHA-256, bytes): **338 assemblies, 205 MB, 549 602 methods, 2.997 M rows in 33 tables, 450 318 / 504 848 signature blobs normalized, 3.29 M token slots, 0 opaque bodies, 0 fallbacks** besides the native PE; Wasm 58 modules as above. Tests: table-driven signature, CIL body, opcode table, coded-index, width-transition (3 thresholds), tamper (reference / payload / meta), determinism, fixtures, Wasm instruction forms, LEB, directory, round trips at padded widths; 20 s fuzz per entry point, clean: CLR parse 531 K execs, CLR decode 10 K (large cached inputs), Wasm parse 2.3 M, Wasm decode 906 K. Final run: gofmt, vet, `go test ./...` (47 packages) clean.
`INDEX_SUBSTRATE_PARTIAL`: `idxref` is now used by three formats — `Hash`, `ClassIndex`/`PrefixIndex` (all CLR and Wasm references), `AutoK0`, `PackComp/SplitComp`, `Sec` and the extracted cutters — but slot walkers, identity definitions, the stage order (CLR: layout < keys < signatures < rows < tokens; Wasm: types < definitions < elements) and layout items are format-local, so no common slot walker exists to promote. READY would need a shared `Slot`/stage-resolver contract; nothing here argues for it. `repz3` gained one constant (12); no generic SYMBOL/INDEX/TOKEN role. No `KindWasm`.
