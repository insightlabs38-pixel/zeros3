## 1. Identity and type system
Three equality levels. **Byte identity**: SHA-256 of payload (one physical blob per digest). **Canonical semantic identity**: `CID = SHA256(domain ‖ descriptor ‖ payload length ‖ payload digest)`; the descriptor is kind (tensor/bytes/file/column/validity), version, dtype, shape, ordered flag and kind-specific extra bytes; payloads are little-endian, C order. Same bytes typed F16/I16/U64, reshaped, or BYTES get *different* CIDs but one blob (unit-tested; pythia `st_i16_reinterpret` stores 0 new bytes yet 71 distinct semantic records). **Value-level relation**: a different dtype/layout/quantization is never an alias: it is a *derived* component whose record carries parents, an op pipeline and an exact sparse residual; the payload digest is the final authority. CID excludes the physical form, so a raw component can later be re-expressed as derived (or back) without changing any recipe; the index (`payload digest → CID`, `elems → CID`) is rebuilt by scanning `comps/` (self-authenticating records; no global namespace). NaN payloads, ±0 and signaling NaNs are bit-exact; narrowing quiets sNaNs, which surfaces as a residual, not an alias.
## 2. Reconstruction architecture
`file = recipe(LIT | REF(cid) | SPAN(cid,off,len))`; recipe carries length+SHA-256, replay fails closed (digest, length, short writer, span range, missing/corrupt blob, truncated/oversized claims). Derived components use a small reusable op set (the B4 starting vocabulary): `perm` (reshape+axis permutation), `gather` rows, `bswap`, `convert` (F16/BF16/F32/F64, int widening), `q8_0`/`q4_0` (GGML quantizers), `slice`, `prepend`, `plain>offsets|data` (Parquet byte-array ↔ Arrow offsets), and *codec ops reusing existing exact primitives*: `deflate` (Z3 IR skeleton+units), `recipe` (nested recipe), `parquet` (kind-10 codec). Closure limits: depth 4, fanout 1024, cycle detection, 2 GiB per materialization; `Rederive` proves a new form and checks depth/cycles for the whole store before replacing a record. Decode needs no Python/torch/native tool (all producers/oracles are harness-only). Fresh-process proof: `z4b3 replay` opens only `blobs/ comps/ recipes/`; `verify_replay.py` hashes outputs independently.
## 3. Lanes implemented
**Tensor (primary)**: Safetensors, GGUF, ONNX initializers (own strict protobuf walker, raw_data), PyTorch ZIP (stored members + non-executing symbolic pickle reader; strided storages typed in storage order). Discovery never trusts names: exact payload digest, then proven layout (all axis perms rank≤4), then value relations (float convert, Q8_0/Q4_0 quantize, optional transpose / row gather, llama head-interleave recognized as a 20-byte `perm`), candidates ranked by a layout-invariant magnitude signature (ranking only), every acceptance proven by SHA-256. **Git/tar/OCI**: tar members and Git blobs become one format-neutral `file` component (Git "blob N\0" and tar headers/padding are framing); tar.gz/OCI layers and zlib pack/loose entries are exact `deflate` derivations from plaintext; delta entries keep their compressed program bytes. **Columnar**: Arrow IPC (strict flatbuffer reader) and Parquet share per-column dense-value / PLAIN byte-array stream components; UNCOMPRESSED PLAIN pages by direct spans, and *any* Parquet the kind-10 codec accepts (Snappy/Zstd, dictionary) via the `parquet` op over whole-column value components.

## 6. Group-aware admission
SmolLM2, the same 5 files in two orders. Forward (BF16 first): 272.2 MB. Reverse online (Q8_0, F16, ONNX×2, BF16 last): 438.0 MB (1.61×) because early lossy forms become roots. Offline `optimize` (largest-first, re-express each raw component as a proven derivation of any non-descendant, depth ≤4, 48 s): **283.1 MB (1.04× of forward)**; F16 can even serve as a parent of BF16 for in-range values (information-lossless), which is why online reverse is 1.6×, not 4×. Negative: a "star re-rooting" oracle clustered by signature reached only 374 MB (clusters split/merge wrongly) and was removed; true min-cost arborescence over a cluster graph is open. Columnar/Git results are order-independent (canonical components are the roots).
## 7. Performance, memory, ranges

Dependency depth ≤3 observed (gz→tar recipe→file→chunk), derived tensors depth 1–2. Range reads, bytes read from stored blobs per request (CDC = compressed chunk bytes intersecting): F16 GGUF 4 KiB/64 KiB/1 MiB → 4.2 KB/66 KB/1.05 MB vs CDC 84/142/1107 KB; Q8_0 (block-local) 7.8/123/1973 KB vs 90/136/1117 KB; Safetensors raw 4.1/65/1048 KB vs 97/160/1137 KB. **Permuted layouts are the cost**: transposed ONNX/column-major torch need ≈12 MB (the whole Pythia embedding, ≈3000×) per 4 KiB request (SmolLM2 ONNX FP32: 1.1–1.8 MB, i.e. 270–430×), with only 64 permutation runs allowed before whole-tensor fallback. Hence: archive/cold, or keep the layout-owner form raw.

## 9. Negatives and unresolved (classified)
- Cross-format *byte-identical* tensors/blobs: gain mostly already present (CDC, Model identity, B1): equality detection was complete; headroom is small.
- Real-world cross-dtype/layout (bf16→f16/f32/Q8_0, transpose, llama permute): large; achieved here. Not generalized: K-quants/IQ types, Q4_0 only vector-validated, per-producer rounding must match (residual absorbs mismatches), GGUF big-endian and external-data ONNX not parsed, shared/overlapping PyTorch storages left opaque.
- Parquet/Arrow with nulls, narrow ints (Parquet widens to INT32), dictionary Arrow: semantic identity exists, canonical form not implemented (validity/def-level ↔ bitmap and width ops) — stronger normalization required, **not a KILL**. ORC: semantic equality proven by pyarrow (zlib 5.2 MB / none 7.0 MB vs 6.86 MB for all eight other files) but RLEv2/stripe re-encoding replay is unimplemented: literal today, opportunity ≈ one full copy; open research (the u32 column cannot even be expressed in ORC).
- Git delta entries stay opaque (Git `create_delta` replay needs a GPL port, decided unrealisable in Z3-16); zstd OCI layers not integrated (exact zstd replay exists in Z3-25); tar variants outside tarz3's shapes fall back to chunked bytes.
- Structural: derived forms raise read cost for permuted layouts (§7) and blast radius (one BF16 blob underlies five files); exact DEFLATE analysis is slow (1 MB/s); analysis holds whole files in RAM; fanout cap 1024 forces wide Parquet to fall back.
## 10. Verdict and implications
**CROSS_FORMAT_CAS_NICHE.** For collections that hold several formats of one logical state (HF repos: ST+GGUF+ONNX+quantizations; source released as tar/tgz/OCI/Git; Arrow/Parquet exports) a typed canonical component with proven derivations shrinks retained storage 4× (models), 8× (source packagings) and 6.7× (columnar) versus CDC, 31–49 % beyond independently optimized per-format stores, with byte-exact fresh-process reconstruction. It matters only under representation authority and in cold/archive tiers (additive sidecar costs 1.1–1.25× CDC, replay of deflate-backed forms is 5 MB/s, permuted-layout ranges read whole tensors), and only where producers are exactly replayable; it is not a general hot-path replacement. Next-step options (not started): streaming ingest and windowed relations, index persistence in B2's record/closure machinery.
B4: the op vocabulary above (perm/gather/convert/quantize/slice/prepend/offsets/deflate/recipe/parquet) with residuals and proof-before-publish is the concrete starting set; synthesis should target producer arithmetic discovery (rounding, block quantizers) and null/width/RLE ops. B5: Model delta 2.0 should treat dtype/layout conversions as exact functions plus residual, not numeric deltas (B1 gain was zero here). B6: rank codecs by predictability (snappy/deflate/dictionary ≈ free, zstd explicit recipes ≈ 8 % of file). B7: planner needs group-aware root choice (1.6× order penalty online), closure retention and range-amplification terms. B8: converge on CDC hot + exact semantic forms for cold multi-format sets behind B2 authority.
