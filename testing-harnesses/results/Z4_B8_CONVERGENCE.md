## 1. Executive recommendation
1. **Pursue Option B: a narrow, opt-in, content-keyed representation authority (B2's design) for cold data and for older versions of hot histories, on top of the unchanged CDC hot path.** Authority = body record per content SHA (pin / existing rep kind / exact delta), CDC chunks become a virtual index; decoded caches are disposable. Everything else stays research.
2. **Do not merge or auto-rebase #97.** B8 verified that it merges into current main with zero textual conflict (`zeros3.go` has not changed since B2's base `44d7d58`; 40 hunks, ~3.2 kLOC) and that its authority suite (26 test functions incl. the SIGKILL crash matrix) passes on the merge (66 s) [IC]. The rebase risk is semantic, not textual: ~15 raw `casRead/casStat` sites were rerouted by hand, and nothing proves none is missed (gate G1 below).
3. **B2 as drafted is inert for the headline model workload**: two of three SmolLM2 files (BF16 safetensors and F16 GGUF, 270 MB each; 685 MB logical in total) fall outside its 256 MiB admission window and the 145 MB Q8_0 saves 0.15% as a rep, so authority saves 0.0% on the set while the shipped additive kind 8 costs 2.00×CDC [IC]. B3-class forms save 61% on the same set [IC] but exist only in the lab. Models need windowed encoding plus new forms before authority helps them.
4. **First follow-on batch: `Z4-C1` authority-core qualification** (section 15) — production port of B2's pin/rep/delta forms behind floor 10, default off, with nine decisive gates. Stop if the retire-everything differential run (G1) exposes more than five distinct unguarded call paths, if power-loss replay (G2) ever yields silent wrong bytes, or if a real pilot corpus saves <15%.
5. **Not production directions now**: B7's learned planner (registered rule fails 0/5 folds, §10), generic-VM replacement of DEX/CLR, B3 Git/tar/OCI semantic layer, B5 natural-delta predictors, SquashFS-LZ4, LZ4HC≥10, WOFF2/LZX/LZMA2. **Defer, with a bounded probe**: Parquet-Brotli. **Qualify after C1**: B6 LZ4 decoder in kinds 9/10, B5 narrowing/NRC and GGUF-from-safetensors derivation.
6. The honest economic statement: standalone ratios (0.24–0.7×) become physical only under authority and only for versioned/reusable data. A mix with ≈8% reusable data saves 1–4%; saving ≥5% needs ≈16% of the store in reusable classes (§4). That is a feature for artifact, model, database and dataset stores, not a blanket default.

## 5. B2 representation-authority decision
**Decision: proceed toward productionizing a narrowed B2.** Alternatives: *redesign* (no: content-keyed single-record commit is the right atom; per-manifest locators fail for copies/versions/snapshots/bases and manifest rewrites break journal hashes); *keep experimental* (no: no architectural blocker found, and without authority every Z4 form is a 1.3–2.0× loss); *reject* (no: .27–.82 physical on versioned data; DEX .489 and Parquet .326 reproduced).
**Keep:** `bodies/<sha>.body` (pin/rep/delta, CRC32C, generation+1 atomic rename), closure-checked publish, fail-closed GC, floor 10 raised before first record, offline `authority migrate|revert|status`, virtual chunk index for unchanged sync/bundle/replication, request-local verified-chunk cache, best-of-two group planning, depth ≤2 default, newest-stays-CDC hybrid as default policy.
**Narrow/fix before production:** (a) 256 MiB whole-object cap → windowed/streamed delta (models and DB files are bigger; [IC] 0% saving on 270 MB models); (b) speculative rep staging gives 3–4× peak (DEX 2.17× delta+rep here) → estimate before flush, capacity check; (c) **plan accounting**: value freed CDC as the union of chunks whose every referrer is in the migrating group (physical end-state bytes), in group admission, per-object saving and the best-of-two comparator [diagnostic: Parquet .916→.326]; (c2) per-run bottom-16 sketches → B1's persistent sorted similarity index (12 B/posting, 4.9 µs/query at 100k chunks [RP]); (d) CLI migration/gc need the exclusive lock → background worker with I/O budget; (e) native closure transfer is a library stream, not a negotiated wire capability (bundle/replicate work only by exact materialization; delta-bundle export untested); (f) authority-aware `stats`; (g) floor-lowering path after full revert (today no automatic downgrade: a pilot cannot roll back to an old binary without a tested procedure); (h) `AuthorityRepairObject` and peer repair assume a peer holds the closure.
**Costs accepted:** floor-10 lock-in per adopting store (non-adopting stores keep old floors; old binaries refuse byte-identically [RP]); reads archive 1.3–2.9× slower whole-object, 4 KiB amplification 1.6–3.5× CDC; blast radius up to 12 contents per chunk in a 12-delta chain (mean 3.2) vs 2–4; offline reclamation; +3.2 kLOC (+5.8%) in the one production file.
**B3–B7 interaction:** the form vocabulary (pin / rep kind N / delta) is the integration point. Later forms (LZ4 recipes in kinds 9/10, narrowing/NRC in kind 8, GGUF-derived-from-safetensors) are *new record versions under a new floor*, never new storage layers. A form must beat the best existing form on a group-priced basis (B2: per-object greedy lost: DEX 1.081×, mixed 0.934 vs delta-only .817).

**Interoperability answers.** Similarity deltas: a form of authority (B2's delta), not a separate layer; format-specific decoders stay independent and are chosen per object by group-priced cost. B3 semantic components: archive-only, never first-class CAS objects in the hot namespace — they need depth ≤4, fanout 1024 and whole-tensor reads for permuted layouts; adopt only the derived-file form (GGUF from safetensors) as one record type. B4 VM: stays local to LLVM/PDB (generic lost on DEX .70 vs .49, CLR ≈ delta, Wasm object tax 132 B/step). B5 coders: promote narrowing/FPE/NRC as numeric codecs *inside kind 8*, not as general codecs; predictors stay lab. B6: share `lz4z3` replay between kinds 9 and 10 as a recipe codec under a new floor, no new kinds. Measured combinations beyond the best single mechanism: B4 normalization + B1 deltas on LLVM (.51 vs .81 with deltas but no normalization [IC]) and PDB column predictors (.41 vs B1 whole-file .63 [IC]), B3 joint vs independent per-family stores (31% source, 49% columnar), B1 hybrid on CLR (.655 vs .839 generic/.898 format); none measured on top of B2 authority. Excess object counts: LLVM 3,630 objects for 6 releases, Wasm function granularity (negative), B3 1,363 components for 5 files — each object costs ≥132 B plus a locator, so form selection must be per group, never per object.

## 8. Workload and performance tradeoffs
Measured by B2 (CDC → archive): whole-object GET 194→103 MB/s (tar), 132→46 (CLR), 143→79 (DEX), 704→434 (Git); 4 KiB 635→1845 µs (tar), 735→2368 (CLR); amplification 23–37× → 33–85×; 64 KiB 3.2–16×. Hybrid keeps 42–85% of CDC whole-read throughput. Structural REP bodies without range decoders cost 50–640 ms per 4 KiB and 13–96 MB/s whole: **archive only**. Encode/migrate: tar 187 MB 5.9 s (delta-only) / 28.6 s (best), RSS 447–540 MiB; DEX 133 s on a loaded machine (RSS 176 MiB); B3 16 MB/s, 1.95 GB; B5 0.6–13 MiB/s encode, 2.4–4.1 GiB replay RSS; B4 7 MiB/s. **Cold archive**: accept 2× reads, take 2–4× disk. **Warm history**: newest stays CDC. **Hot/one-off**: untouched. Not measured anywhere: cold-device latency, concurrent PUT/GET under migration load, >10^4 objects, capacity exhaustion during migration beyond injected ENOSPC, streaming ingest memory for models. These are C1/C2 gates, not telemetry guesses.

## 9. Reliability, compatibility and migration risks
**Invalidates the architecture if found:** silent wrong bytes after a crash at any fsync/rename cut (B2: 29 SIGKILL kills but no power-loss reordering, no dm-flakey); a pervasive set of unguarded raw-CAS sites (25 `casRead/casStat` call sites on main; B2 found 4 classes only by tests: replication 404, copy, restore, rep-build); GC deleting a live base.
**Prerequisite to fix:** recovery cost of a corrupt base (no CDC fallback after reclaim; needs a peer with the closure); floor-10 rollback; windowing above 256 MiB; migration headroom; native closure on the wire; lock-free background maintenance; scale of reachability/virtual-index rebuild (O(live manifests), 100 ms TTL) at 10^5–10^6 objects; float-computation decoders (quantizers, affine) never run off amd64; producer-version drift (LZ4 ≤1.9.4, ggml builds) fails as explicit-recipe bloat (55–115%), not as wrong bytes, but admission must price it.
**Bounded by configuration:** depth ≤2, fanout ≤4, per-object window, hybrid default, creation off, offline mode, pins, scrub schedule, redundant peers.
Journal/manifests are immutable and unchanged, which is B2's strongest compatibility property. Old binaries refuse before mutation (47 refusal cases at A1; B2 old-binary matrix [RP]). Research code volume (≈27 kLOC across the seven lab modules, 45 kLOC with data and harnesses) is not shipped and is not a production maintenance burden unless ported.

**Operational checklist (S3 engine view).** PUT success/latency: unchanged, creation is offline/background; whole-object GET: 1.3–2.9× slower archive, hybrid 0.42–0.85× CDC; random range: 1.6–3.5× amplification, REP bodies without range decoders 50–640 ms; streaming ingest: untouched (lab encoders hold whole files: B3 1.95 GB, B5 2.7–4.1 GiB); memory: B2 447–540 MiB at 256 MiB object cap; capacity exhaustion: migration peak 1.5–4.2× (safe garbage on ENOSPC); cancellation/concurrency/snapshots/versions/copy: covered by B2 tests that pass on main; repeated compaction/GC: tested but not in loops; repair: needs peer; replication/sync/bundle: exact via materialization, native closure not on the wire; observability: `stats` is not authority-aware; safe defaults: off, floor untouched until `authority migrate`.

## 10. B7 protocol and planner audit (`../z4/b8/b7_protocol_audit.txt`, reruns `b7_perturbation.txt`)
**Timing.** `protocol.json` is a single commit, `eef665b` (2026-11-07 21:55), before the library (`a0162c0` 22:12), policies (`1f983de` 22:30) and results (`491ac2a` 00:03); it was never edited, so there is no tampering [IC].
**Registered rule applied as written** (target = `combined`; baselines = always-CDC, greedy, premium-cap-0.10, Z3-36 EV; best-in-hindsight per fold; both books): `combined` wins **0/5 folds in both books**, mean improvement −52% (A) and −135% (B), worst fold 1.58×/4.13× CDC → **PLANNER2_NOT_JUSTIFIED**. The published `PLANNER2_SPECIALIZED` substitutes `auto`, a preset introduced after the protocol and absent from it. Preserved original finding: the registered sophisticated planner fails outright; corrected interpretation changes the label (SPECIALIZED→NOT_JUSTIFIED), not the production decision.
**Substituted policy, same rule:** `auto` wins 4/5 (A) and 3/5 (B), mean improvement **+6.6% (A, cluster-bootstrap 95% CI +3.2…+9.9%)** and **+0.03% (B, CI −3.6…+3.6%)**; worst fold 1.087×CDC (managed, B); 44 of 160 B worlds lose to CDC. Dropping the SST fold lowers A to +5.6% and B to −2.2%; dropping managed lowers A to +4.3%. The report's "+3.3%" averages the two books. `lifetime` (5/5, 4/5) and `class-prior` behave the same; no policy meets "both books".
**Why complexity loses.** `combined` vs `combined-no-defer` (A, mean over worlds): final bytes .832 vs .668, peak 1.16× vs .76×, 50 enqueued tasks vs 22; in book B almost nothing is archived (final .988) yet cost is 1.90×: paid analysis CPU and I/O without bytes saved. Cause = **deferral economics, not features**: ablating group/read/lifetime/lineage/class moves `combined` <1%; ablating deferral moves it 1.085→.723. Writing CDC first and archiving later pays double storage plus migration I/O; a 200 ms synchronous budget makes every lineage take that path. This is a scheduler/pricing property, not a fundamental limit of authority: a static operator-run cold migration pays neither.
**Modeling error.** Candidate proxy error 5.1% mean, 124% max; later-stage `std` is modeled for 24 of 44 non-CDC scheme series. B8 reran the evaluator on perturbed, loader-valid series (`b7_perturbation.txt`; seed 11, scenarios S1–S2, all five folds, both books): (i) unperturbed rerun reproduces the published ordering (A: class-prior/lifetime/auto .70, EV .75, `combined` 1.05; auto +4.8% over best simple, 3/5 folds); (ii) **independent lognormal noise** (σ=.10 on measured, .25 on modeled numbers) leaves the ranking unchanged (A: auto .680, EV .733, `combined` 1.04; auto +5.2%, 4/5 folds; B: +0.1%, 2/5) — random model error does not change the policy ranking; (iii) **systematic optimism removed** (+30% first-sight, +10% later stages for every non-CDC scheme) *reverses* it: auto .956 vs premium-cap .909, EV .913, `combined-no-defer` .889 in A; auto wins 0/5 folds in both books (−8%, −11%) and the best policy saves only 11%. So the planner's edge is real against random error but fragile against exactly the error the simulation cannot exclude — a systematic underestimate of representation cost — and the modeled `std` series (24 of 44) are where such bias would sit. Real telemetry or physical rows must replace them before any adaptive rule is trusted. (The heavy-tail variant was not run; `b7_perturb_series.py heavy` is provided.)
**Reverse bases** (`reverse_base.txt`). B7's delta model has forward bases only. B2's measured newest-stays-CDC hybrid keeps **0–84% of the archive saving** (CLR .84, tar .54, SQLite .34, DEX .28, Git 0, Parquet 0) while B7 priced it +47–70% *worse than CDC* for DEX/Parquet/Git (1.47/1.70/1.55 vs measured .965/1.001/1.000) and 10–20 points too high for tar/CLR. The hot/cold policy survives a proper comparison — hybrid beats CDC where B7 also chose it (CLR, tar) and ties it elsewhere — but B7's hybrid-vs-archive rankings rest on wrong prices; at equal depth 2, newest-as-base order beats forward order on CLR ×5 (.728 vs .817 [IC]), so a forward-only model is structurally pessimistic.
**Outcome.** No adaptive planner is justified. Production policy = static per-store/bucket operator rules (format allowlist, minimum object size, age ≥ N days or "older than newest K versions", group-priced best-of-two at migration time), with telemetry (read mix, version fan-out, class sizes) collected first. Revisit a learned rule only if telemetry shows a misprediction cost the static rule cannot capture.

## 11. Outstanding B3/B4/B5/B6 research decisions
*B3.* Nullable/narrow-int/dictionary Arrow: extension of a synthetic lane, would not change architecture → low. ORC: oracle = one copy of a 7 MB table, absent prevalence → defer. Git delta interpretation (GPL port, Z3-16 unrealisable) and zstd OCI layers: B1 already gets .997 on OCI, not decision-relevant. **K-quants/IQ**: highest relevance (Q4_K_M is the common GGUF); B5 did Q4_K/Q6_K, Q5_K and IQ remain → research item #2. Streaming ingest and persistent index: engineering prerequisites (C2), not research. Range amplification: policy (keep the layout owner raw).
*B4.* DWARF and ELF/PE adapters were declared open at B4's close and are the only unattempted item with a large addressable population (every native binary history); Z3-12/13/35 normalized ELF/PE on locally built Go binaries (not shipped release histories) and B1 generic got .414 on controlled ELF. Decisive experiment: six real shipped ELF releases (distro packages, Go/Rust binaries) under B1 generic vs Z3-12 normalization vs authority delta, charged to physical bytes; go if best ≥15% better than delta. LLVM skeleton IDs (≈5% of O2 bytes), PDB sequence-point op (−8% of PDB), range-indexed reconstruction (archive-only, not needed), graph memory (700 B/node), other clang versions: no architecture change.
*B5.* Qwen2.5-0.5B lab Model8 baseline OOM (>10 GiB): the table substitutes B1's PXR oracle (.698; B5 pool3 .594 = −15%) and Z3-29's 2-state pair (.645 cumulative, already above B5's 5-state .568). The claim "B5 beats Model8 by 4–25%" is therefore supported for four families and unverified for Qwen, but it cannot flip the conclusion because B5's gain comes from first-sight coding and narrowing, which the B1 oracle already shows. Natural weight histories are noise-limited, not proven incompressible: non-causal interpolation reaches 7%, optimizer/data-order side information is untested. Promote coders and quantizer reproduction; keep predictors research.
*B6.* Parquet-Brotli: the −62% oracle (76.9→29.0) is as large as LZ4_RAW's. B8 probe [IC]: libbrotli q8/lgwin22 reproduces **72/72** pyarrow pages in 3 files (q5–q7,q9 partially; lgwin 18/24 never), so *parameter prediction is trivial*; the blocker is a bit-exact Go port of Brotli q8 (hasher, block splitting, context modeling; my estimate several kLOC, 3–10× the 1.5 kLOC lz4z3) tied to libbrotli versions. Commit nothing until a ≤2-day probe shows (a) Brotli is ≥10% of Parquet bytes in ≥3 public sources (footer survey of ≥200 files), (b) ≥95% of pages reproduce with one config across pyarrow, Spark/parquet-mr and DuckDB writers, (c) libbrotli 1.0.x vs 1.1.x outputs agree. LZ4HC≥10/linked: open but no consumer measured; WOFF2/LZX/LZMA2 negative stands.

## 15. Final go/no-go and answers
1. **Enabled/restricted:** decoders for kinds 1–12 stay; creation stays off; `prefer` is not a disk-saving feature. 2. **B1 as a layer:** no; as B2's delta form: yes. 3. **B2 worth productionizing:** yes, narrowed. 4. **Narrow vs redesign:** narrow (§5). 5. **B3 semantic CAS:** not now; derived-form subset after C2. 6. **B4 replacing bespoke formats:** no. 7. **B5 promotion:** narrowing, FPE/NRC, quantizer reproduction (qualified); not predictors. 8. **B6:** LZ4 SST/Parquet decoders after C1; Brotli probe; rest no. 9. **B7 planner:** no (registered rule fails 0/5). 10. **Top risks:** unguarded raw-CAS paths, power-loss ordering, base-corruption recovery, floor-10 rollback, windowing, float/arch determinism. 11. **Research:** §13. 12. **Architecture:** Option B. 13. **First batch:** C1. 14. **Stop/change:** below.
**Adversarial results.** Few related versions → 1–4% saving, authority stays off, cost is carried code only (Option A fallback). Mostly hot data → hybrid only, saving 24–27% on suitable families, nothing on Parquet/Git/DEX. High PUT concurrency → untouched (creation is offline/background). Store nearly full → migration peak 1.5–4.2× is the binding limit; admission must refuse (B7 shows 11 refused PUTs at 12.5% headroom under deferral). Corrupt base → fail-closed, explicit, needs peer. Repeated GC crash → B2's kills complete on retry; add repeated-crash loop (G8). Old binaries → refusal verified, replication via materialization. Wrong admission → static rules bound loss to one migration; revert exists. Workers lag → none in C1. Long chains → depth ≤2. Slow encoder on large file → CPU break-even table; slow encoders operator-only. Doubled complexity for 5% → the stop rule: pilot <15% returns to A. Underestimated cold histories? Partly: B3-class forms (4–8× on multi-packaging) are real but need C2/C5; C1 deliberately builds the substrate first.
**Z4-C1 acceptance (exact).** Scope: B2 pin/rep/delta + floor 10 on current main, default off, no new codecs/planner. G1 retire-everything differential: a test mode that migrates and retires every admissible object after each PUT and runs the unchanged root S3/CLI/sync/bundle/replicate suite — all pass, ≤5 distinct unguarded paths found. G2 power-loss replay: syscall-trace cut/reorder of migrate, publish, gc, repack, revert — every cut opens, acknowledged objects exact or explicitly repairable, zero silent corruption. G3 scale: 10^5 objects/10^6 chunks reachability + gc within agreed time and RSS. G4 old/new five-generation matrix incl. portable bundles and replication. G5 windowed delta 1 GiB object within RSS bound. G6 hybrid GET ≥0.5× CDC and 4 KiB amplification ≤4× or the object is refused. G7 revert-all + floor-lowering with old binary reopen. G8 repeated-crash loops at every gc/repack/revert boundary and base-corruption peer repair. G9 plan accounting: decisions use physical end-state bytes; Parquet 8-revision Snappy chain rep-only ≤0.40×CDC, DEX ≤0.5×, no family worse than today's planner; SQLite, SST, Git, DEX, CLR rep-only re-measured because B2's rep numbers may carry the same bias. Merge only if full root suite (incl. race) passes, defaults and non-adopting stores are byte-unchanged, and `zeros3.go` stays single-file stdlib-only.
**Change course:** G1 >5 paths or G2 silent corruption → keep Option A, publish B2 as a design note; pilot saving <15% → Option A; windowing cannot bound RSS → Option D; floor-10 rollback unsafe → do not ship migration.
