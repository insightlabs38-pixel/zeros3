# Z4-B4 — Generic graph/ID normalization and reversible transform synthesis
Verdict: **GRAPH_NORMALIZATION_PARTIAL** — research only (RESEARCH_ONLY policy), production source unchanged. Branch `z4/graph-normalization` (same commits also pushed to the runtime branch `branch/laughing-hawking-s2mltq`), base main `1b7f8c6` (verified = origin/main at start). B1 #96 and B3 #98 merged; B2 #97 and drafts #80/#81 untouched and not imported. Code `testing-harnesses/z3/graphnorm/` (≈7.5 kLOC incl. 1.3 kLOC tests and the driver), driver `cmd/z4b4`, reproduction + pins [README](../z4/b4/README.md), raw results [evidence](../z4/b4/evidence.txt.gz).
**Short answer.** A reusable exact substrate exists and works: graph identities (SCC-aware), a bounded 22-op reversible VM, an automatic synthesizer (per-function programs, per-column predictors, candidate choice by charged cost) and proof-before-accept. It beats CDC *and* B1 on **LLVM bitcode (0.51×CDC, 0.68×B1)** and **Portable PDB (0.41×CDC, 0.66×B1)**, both with fresh-process byte-exact replay. It does **not** replace bespoke DEX/CLR (DEX generic 0.70 vs bespoke 0.49 of CDC) and is negative on Wasm. The graph-identity engine itself is decisive only for LLVM; PDB/DEX gains come from the VM's column-predictor synthesis. Nothing here is a physical saving without B2-style authority (additive sidecar ≈1.4–1.5×CDC).
## 1. Generic graph model (`graph.go`)
`Node{Class, Flags, Lit, Out(ordered), Set(multiset)}`, edges by temporary handle; layout fields never enter a node. Flags: `Opaque` (identity = literal only), `Unknown` (poisoned). Result classes per node: **None** (unique structural identity), **Duplicate** (identical structure; occurrence index), **Symmetric** (automorphic orbit or exhausted search), **Poisoned** (dangling/unknown reference reachable), **Opaque**. Only *None* may be used as a reference key; duplicates/symmetric/poisoned fall back to literals (tested: ambiguous key at decode is an error, never a pick). Three equality levels are kept apart: exact bytes (final SHA-256), structural identity (hash of canonical content, permitted renumbering only), and similarity (never accepted without exact replay).
## 2. Identity and matching algorithms (`graph.go`, `match.go`)
Implemented and compared: tagged local hash; ordered/unordered 1-WL refinement (`RefineIdentities`); **SCC-aware Merkle identity** (`SCCIdentities`: Tarjan condensation, acyclic nodes hash children, cyclic components canonically labeled by colour refinement with in-neighbours + bounded individualization-refinement, work budget 3 M updates/component); duplicate-occurrence classification; `Match`: exact-unique anchors → neighbourhood agreement with zero conflicts and mutual-unique-best → exact bipartite assignment (Kuhn–Munkres + uniqueness proof) for ambiguous partitions ≤24 → order-pairing of equal duplicate classes (flagged weak). Heuristic similarity is never proof; every match carries its basis.
- Property tests: identities invariant under random renumbering + set-edge shuffles (60 random cyclic graphs); symmetric rings, K6,6, 3000/20000-node rings stay Symmetric within budget (20k ring 1.1 s); ordered edges order-sensitive, set edges not; dangling edges poison transitively; mutual recursion distinguished.
- Random edit model (5 % delete / 5 % relabel / 5 % insert + renumber, 40 graphs): 3891/4560 true correspondences found (85 %); 1/1907 exact-basis matches disagrees with edit history (a deleted node coinciding with an edited neighbour — structurally identical, hence sound for sharing).
- **Real graphs** (anonymous function graph of SQLite: node literal = abstract body, callee set edges; names only as truth), 4 release transitions, 1.5 k functions each: local 1335/1353/1030/478 matched, refine 1284/1308/855/240, SCC 1261/1306/839/240 (context hashes are stricter: a changed callee changes callers); **0 wrong matches in all 12 runs**; 73–84 functions/graph (≈5 %) are Duplicate/Symmetric and excluded from exact basis. Not claimed: semantic equivalence, only identical canonical factorization.
## 3. LLVM bitcode (primary lane)
Exact bitstream tree (`bitstream.go`, rejects any non-canonical VBR/padding/length word; parse→write must equal input). `llvm_module.go` builds one module graph (types, attribute groups/lists, globals, constants, module metadata) and 4 key tables (value/type/attr-list/metadata, 4-byte keys from SCC identities): named globals keyed by name (leaf), **private/unnamed globals by content** (`.str.N` suffixes are layout), constants/types by structure, structurally identical *distinct* metadata (every loop id) disambiguated by referrer context (first referencing function + ordinal) — the controlled "type insertion" case fell from 164 KB to 35 KB of new function objects after this. `llvm_tmpl.go` turns each function block into a template: relative value operands to module values, absolute value/type/attr/metadata ids, function-local absolute ids (uselist, switch, aggregate) become symbolic tokens (extern key, or offset from the table size); forward-reference type insertions, value-numbering (void calls), PHI signed refs, METADATA_ATTACHMENT, function-local metadata handled; unsupported records stay literal. 25.6 % of 1.45 M operands become symbolic (absolute extern refs — mostly types, also switch/aggregate values and metadata — 206 k, relative extern values 117 k, attr/md+1 18 k, function-local abs 17 k, signed-rel 9 k, local-md 4 k). Skeleton (module-level records) is serialized byte-aligned but **not** ID-normalized.
Corpus (real release *sources* compiled with the local Ubuntu clang 18.1.3, `-g0`, x86_64-linux; not shipped bitcode histories, and not the 19.1.7 of Z3-43): SQLite amalgamations 3.45.1, 3.45.2, 3.45.3, 3.46.0, 3.46.1, 3.49.1 at O2 (6 × 2.7 MB) and four of them at O0; 8 controlled states (200+ external functions: early/late function, early type, early global, constants, rename, restored). ## 4. Portable PDB (second deep lane) and DWARF
`pdb.go`: strict metadata-root/stream parse, heap streams opaque components, every fixed-width table of the 8 PDB tables expanded to column-major varint streams by `OpTable`, predictor per column (raw or zig-zag delta) chosen by packed size; all other bytes literal; exactness proved by self-replay. Real data: 5 official Newtonsoft.Json netstandard2.0 symbol-package PDBs (12.0.3, 13.0.1, 13.0.2, 13.0.3, 13.0.4; public NuGet).

|cumulative|597,782|595,271|374,301|314,407|**247,492**|
First release 91.9 k vs CDC 113.8 k (no premium). Predictors chosen on revisions 1–2 equal the per-file search on the 3 held-out releases (0 differing columns; 11 of 24 columns are delta, e.g. MDI.SequencePoints, LocalScope.Method/VariableList, ImportScope.Parent, CustomDebugInformation.Parent/Value). ## 6. Restricted transform VM (`vm.go`)
Flat, loop-free, bounded (≤64 M ops, output limit, depth 64, ext ≤1 M, length scopes ≤64), no callbacks. Byte family: `LIT COPY GATHER U(width,endian) LEB(signed,min width preserved) CINT LEN_BEGIN/END CKSUM/MARK DERIVE(adler32/crc32/sha1/sha256 into earlier offset) PATCH ZERO ALIGN TABLE(column predictors) STREAM`. Bitstream family: `ENTER END DEFABBR REC(abbrev-implied code/arity) SETINST` plus token kinds `LIT, XREL, XABS, XABS+1, LABS, XRELS, LMD, ESC` resolved through four key tables; every record is validated against its abbreviation (literals equal, scalars fit) before emission. Derivations (lengths, checksums, relative refs, table sums) are only used because replay was proven; the caller verifies final length + SHA-256. Mapping to the requested ops: COPY/MASK(ZERO)/WRITE_LITERAL/WRITE_REF_{FIXED,VARINT/CINT,LEB,VBR via tokens}/PERMUTE (= recipe step order)/CONCAT (sequential execution)/SLICE+GATHER/DERIVE_LENGTH/DERIVE_CHECKSUM/PATCH residual. Not used from B3: semcas tensor ops (kept out deliberately); B3's recipe-with-digest + proof-before-publish discipline is reused (`recipe.go`). Decoder is stdlib-only (recipe/replay additionally use the B1 `simdelta` research module for stored delta objects).
## 7. Automatic synthesis evidence
- Per-function programs are generated from parsed evidence (role grammar × key tables × value numbering), executed against the original block, and replaced by the literal program on mismatch (never needed: 0 fallbacks).
- Policy search over the 6 reference classes (greedy coordinate descent, trained on the first 3 releases, hybrid cost): all classes stay on; each ablation costs +2.9 % (types), +26.5 % (values), +8.4 % (attrs), +2.9 % (metadata), +9.5 % (function-local abs ids), +2.9 % (local metadata) — values/relative refs dominate. Held-out check on the full 6-release history is unchanged (6,396,861 vs no-normalization 10,101,107).
- Column predictors (PDB/DEX): learned on 2 PDB releases, identical on 3 held-out; DEX search picks delta for sorted id columns.
- Component representation (direct vs B1 delta against ≤3 retained versions, depth ≤2) is chosen by charged encoded size, including the base dependency being retained.
- Honest limit: roles come from an LLVM/PDB grammar written by hand; the synthesizer selects, verifies, demotes and prices them, but does not discover new record layouts. A format with an unknown grammar still needs an adapter.
## 8. Byte-exact proofs (fresh process, independent hashing)
`z4b4 llvm-store|prog-store` writes only `recipes/` + `objs/` (simdelta wires, every object charged as stored); `llvm-replay|prog-replay` runs in a separate process (cwd `/`), reads nothing else; `verify_replay.py` (no Go) compares SHA-256 and size with the manifest and the original. **26/26 admitted artifacts MATCH**: SQLite O2 6/6, O0 4/4, controlled 8/8, PDB 5/5, DEX 3/3. Store replay of the 6 O2 releases (16.4 MB, delta depth ≤2): 1.61 s. In-test: every one of 120 sampled stored objects corrupted by one flipped byte ⇒ replay fails closed; missing object, stale id table (other release's), truncated/over-long recipes, non-canonical recipe varints all rejected; 8.6 k bit-flipped bitcodes: 6,079 accepted and reconstructed exactly, 2,577 rejected, 0 inexact; PDB 2 k random mutations: accepted ones exact; random bitstream trees round-trip; truncation sweeps.
## 9. Hostile/ambiguity coverage
Duplicate identical nodes, structurally identical distinct nodes (loop ids), cyclic/mutually recursive graphs, symmetric rings and bicliques, dangling and unknown references, conflicting match candidates (assignment uniqueness proof), unknown record codes, varint/LEB width (non-minimal LEB preserved via min width; non-minimal VBR rejected), width/overflow in OpTable and U, relative-reference underflow, short column streams, absurd row counts, unbalanced block/length scopes, malformed or oversized programs, output/ops limits. Fuzz (10 s each, `go test -fuzz`): VM (0.8 M execs), bitstream→encode→decode, recipe parser, PDB+DEX; fuzz found one real defect (recipe parser accepted non-minimal varints — now rejected, canonical re-marshal required). No race-sensitive code (single-threaded).
## 10. Performance and scaling (single thread, this container)
SQLite 3.49.1 O2 (2.6 MiB, 10.8 k graph nodes/28.5 k edges): parse + exactness proof 20.6 MiB/s; module analysis + SCC identities 18 ms (1.7 µs/node); full encode with per-function VM proofs and self-replay 7.1 MiB/s, VmHWM 146 MB; VM decode 35 MiB/s; fresh replay incl. delta resolution ≈10 MiB/s. Graph engine (synthetic DAG): 100 k nodes SCC identity 89 ms, 1 M nodes 1.3 s but **≈700 MiB heap** (≈700 B/node — too heavy for 100 M-node graphs; needs compact IDs); matching 1 M renumbered nodes 2.7 s (978,965 found: 902 k exact, 58.8 k context, 18 k dup-order). Matching is hash-based, no O(n²) over whole objects; quadratic work only inside ambiguous partitions ≤24. **Range reads are not supported below whole-object replay** (pieces carry no output length; adding 4 B/step would let a read touch id table + BLOCKINFO prefix + one template ≈ 180 KB compressed per 4 KiB request, ~1.3–3× CDC's 64–142 KB; estimate only). Dependency depth ≤2 deltas + 1 recipe level; fanout 1.

## 12. Conclusions: negative vs unfinished, and reuse for B5–B8
- **Established**: ID/offset churn in LLVM bitcode and Portable PDB *is* factorizable exactly; the stable part pays for the reconstruction metadata with room to spare (LLVM −49 % vs CDC, −32 % vs B1; PDB −59 % / −34 %). Referrer-context disambiguation and private-name-by-content are required, not optional.
- **Negative here**: DEX (bespoke wins, generic misses code-item operands); Wasm (object tax ≫ body savings, B1 wins); CLR (bespoke ≈ B1); function granularity needs ≥ several KB bodies. Not KILLed anywhere: the DEX gap is an *insufficient adapter* (needs insn-walker tokens, reusable `OpRec`-style tokens already exist), Wasm needs coarser chunk grouping, not a rejected mechanism.
- **Unfinished**: module-level skeleton ID normalization (≈135 KB/release raw, 67–129 KB after delta), LLVM debug-info (DI*) records (module metadata marked poisoned), sequence-point line op (oracle −8 %), recipe delta coding, piece-indexed range reads, DWARF and ELF/PE adapters, compact graph memory, clang 19 and published-bitcode histories, hiredis (GitHub not reachable from the sandbox; SQLite substituted).
- **B5**: dtype/layout conversions fit the VM as exact functions; reuse `OpTable` predictors for index tables. **B6**: nothing codec-related changed. **B7**: planner must charge per-object tax (36+96 B), first-sight premium (+22…50 %), recipe refs and the depth-2 delta closure; normalization pays only for multi-release retention (≥2 releases). **B8**: keep CDC hot; LLVM/PDB normalization is a cold-tier candidate behind B2 authority; DEX/CLR stay bespoke.
